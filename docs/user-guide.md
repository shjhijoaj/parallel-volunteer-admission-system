# 课选操作与维护

## 首次使用
安装 Java 17，双击根目录“启动系统.cmd”。源码首次启动需要 Maven 下载依赖；带 JAR 的发行包不需要 Maven。打开 8088 端口，管理员账号 admin，初始口令在 data/admin-credentials.txt。

1. 登录管理员，创建新的课程批次，说明对象、优先分依据、是否允许调剂及截止时间。
2. 草稿阶段添加课程：老师、地点、时间、名额必填；也可下载模板后导入 .xlsx（2 MB、200 行以内）。导入是新增，不会按标题覆盖旧课程。
3. 核对后开放报名。此后课程与名额锁定，避免报名中的规则变化。
4. 学生独立注册，加入课程意向、上下调整顺序、选择调剂、确认提交。截止前可修改/撤回；管理员不能代学生报名。
5. 老师在报名列表中审核优先分（0–1000），然后关闭报名。
6. 运行统一分配；先核对导出结果，再点击发布。学生在公示前看不到分配结论。
7. 公示后批次不再修改。下一轮请新建批次，不直接修改数据库来绕过状态机。

## 常见问题
- 页面提示会话过期：刷新页面重新登录，页面自动获取新的 CSRF Token。
- 端口占用：设置环境变量 PORT，例如 8090；不要关闭不属于本项目的进程。
- 无法导入：使用下载的模板，名额必须为正整数，必填字段不能空，批次必须是草稿。
- 报名截止但状态仍是“开放”：截止时间会阻止学生新增/修改/撤回；管理员仍需手动关闭报名再分配。
- 同分怎么处理：以首次有效报名编号排序；修改意向不改变编号，撤回重报会改变。
- 数据库锁定：H2 文件数据库只启动一个应用实例，同一份 data 不能同时被两个进程打开。

## 配置和备份
默认只监听 127.0.0.1。配置项见 application.properties：PORT、SERVER_ADDRESS、COURSE_DB_URL、COURSE_DB_USER、COURSE_DB_PASSWORD、BOOTSTRAP_ADMIN_PASSWORD、COOKIE_SECURE。

停服后备份整个 data 目录，并记录对应版本。恢复时也先停服，再恢复完整目录；不要只拷贝正在写入的数据库文件。管理员密码文件、数据库和日志不上传 GitHub。

MySQL 可使用 jdbc:mysql://主机:3306/库名 连接、独立账号及环境变量配置。当前交付的课程功能验收以 H2 为准；旧录取系统的 MySQL 测试不是新版课程系统的 MySQL 验收。
